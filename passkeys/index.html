01 · hlavní zpráva

Nejde o novou kryptografii.
Mění se životní cyklus credentialu.

Dříve

  • create() a get()
  • passkey jako alternativa hesla
  • credential svázaný s konkrétním managerem
  • omezená synchronizace stavu s RP

Dnes

  • creation → upgrade → sync → recovery
  • passkey jako výchozí UX
  • OS integruje více providerů
  • začíná standardizovaný transfer credentialů

W3C vydalo Web Authentication Level 3 jako W3C Recommendation.

Stabilizované schopnosti

  • Signal API

04 · UX

Passkey už nemusí být jen tlačítko
„použít místo hesla“

Klasické UX

Email: ________ Password: ________ [ Sign in ] [ Use a passkey ]
→

Passkey-first UX

┌──────────────────┐ │ Alice │ │ alice@example… │ │ Use passkey │ └──────────────────┘ fallback → login form

Browser může credential nabídnout přímo při přihlášení a omezit potřebu samostatné passkey větve UI.

Cíl: méně rozhodování, méně login obrazovek5
05 · adopce

Automatic passkey upgrade:
heslo jako migrační cesta

Password login
→
Úspěšné ověření
→
Vytvoření passkey

Starý model

Uživatel se přihlásí, otevře Settings a explicitně si vytvoří passkey.

Nový model

Po úspěšném password loginu může platforma nabídnout nebo provést upgrade na passkey s minimem dalšího UX.

Adopce bez nutnosti učit uživatele nový postup6
06 · account creation

Účet může vzniknout rovnou bez hesla

Tradiční onboarding

email password repeat password password policy recovery...
→

Passkey-native onboarding

account └─ passkey žádné počáteční heslo

Důsledek: účet nemá phishingový password fallback, který by útočník mohl obejít sociálním inženýrstvím.

08 · přenositelnost

CXF

Credential Exchange Format — standardizovaná reprezentace credentialů včetně passkeys.

CXP

Credential Exchange Protocol — protokol pro bezpečný přenos mezi credential managers.

Interoperabilita ještě není univerzální mezi všemi správci, ale ekosystém se posouvá od uzavřených sil ke standardizovanému transferu.
